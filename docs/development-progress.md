## Backend — Risk Engine

Four risk flags are computed server-side on every patient read. Rules are transparent and documented in [`risk_engine.py`](../src/backend/risk_engine.py):

| Flag | Trigger | Severity |
|---|---|---|
| `declining_adherence` | Adherence drop ≥ 25pp between prior 2 weeks and recent 2 weeks | Critical |
| `declining_adherence` | Adherence drop ≥ 20pp | Warning |
| `missed_sessions` | 3+ consecutive missed sessions in last 14 days | Critical |
| `missed_sessions` | 2 consecutive missed sessions in last 14 days | Warning |
| `increasing_discomfort` | Avg pain of 3 most recent sessions ≥ 3pts higher than 3 prior sessions | Critical |
| `increasing_discomfort` | Avg pain increase ≥ 2pts | Warning |
| `irregular_attendance` | Session gap std dev > 6 days (requires 6+ completed sessions, active programme) | Warning |

**Risk level assignment:** HIGH = any critical flag OR 2+ warning flags. MEDIUM = 1 warning flag. LOW = no flags.

**Programme-complete suppression:** If no sessions exist in the last 35 days, the patient is treated as programme-complete and adherence-based flags are suppressed to avoid false positives.

## Synthetic Demo Dataset

**8 patients, 81 sessions** seeded by `seed.py`. All dates are relative to the day `seed.py` is run, so risk and adherence calculations remain valid on any redeploy.

| Patient | Scenario | Expected Risk |
|---|---|---|
| P-001 Margaret O'Sullivan | Stable adherence, improving outcomes | LOW |
| P-002 James Thornton | Attendance collapsed in last 2 weeks | HIGH |
| P-003 Anita Bhattacharya | Perfect history then complete dropout | HIGH |
| P-004 Robert Chen | Consistent sessions but sharply rising pain | HIGH |
| P-005 Declan Murphy | Chronically irregular, multiple consecutive missed | HIGH |
| P-006 Sophie Larsson | New patient, insufficient history | LOW |
| P-007 Yusuf Al-Rashid | Programme completed 5+ weeks ago | LOW |
| P-008 Lucia Fernandez | Combined: attendance collapsing + pain rising | HIGH |

**Verified risk distribution (as of Phase 2):** 3 LOW, 0 MEDIUM, 5 HIGH.

### Known Issue: P-001 Risk Calculation

During Phase 2 verification, P-001 intermittently appeared as MEDIUM risk with a
`declining_adherence` flag. Root cause: the session at exactly the 14-day window boundary
(seeded at `_ago(14)`) was sometimes counted in the recent window and sometimes in the prior
window depending on the exact time `seed.py` ran vs when the risk engine evaluated.

**Resolution applied in Phase 2:** Session dates for P-001 were adjusted to avoid the
boundary (sessions at days 2, 5, 8, 11, 15, 18, 21, 24, 27, 30 — no session falls at
exactly day 14). The window comparison logic was also tightened to use exclusive boundaries
(`now - 14d <= date < now`) to eliminate ambiguity. P-001 consistently returns LOW risk
after this fix. If the issue reappears, re-run `python seed.py` to reset dates relative
to today.

## Known Issues

### Non-blocking: Windows Console Unicode

On Windows with CP1252 terminal encoding, Python's `print()` raises `UnicodeEncodeError`
when output contains non-ASCII characters (e.g., em-dashes `—`, arrows `→`, warning emoji `⚠`).

**Impact:** Console-only cosmetic issue. The HTTP API, database, and frontend are completely
unaffected. The characters are stored correctly in SQLite.

**Workaround:** Already applied in `seed.py` (replaced emoji/special chars in print output).
The health endpoint response body still contains `⚠` which displays as `?` in the Windows
terminal — this does not affect functionality.

### Non-blocking: Recharts Bundle Size

The production build emits a `769 kB` JS bundle (gzip: ~231 kB), triggering Vite's
500 kB chunk size warning. This is due to Recharts. Acceptable for the hackathon demo.
Can be addressed with lazy loading or dynamic imports in Phase 5.
